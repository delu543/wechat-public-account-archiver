# 条件路线：只读公众号推送库

当前推荐使用 [cache-update](CACHE_UPDATE.md)。`weekly-run` 是已有精确公众号推送库绑定时的另一条独立路线，不是缓存不足的自动兜底，也不是本次已经完成部署的插件功能。

```sh
# 只读产品节点
.venv/bin/python main.py weekly-run --plan-only
# 已获准时，只读 helper、salt、首页 HMAC 和已知样本覆盖
.venv/bin/python main.py weekly-run --check
```

## 条件与边界

- 必须由用户单独授权目标账号和仅 `biz_message_N` 范围；已保存凭据不代表可以任意使用。配置缺失/指纹变化只报告一次，不能自动采集密钥、重启或操作微信。
- 当前端到端专用初始化/HMAC/真实推送覆盖未完整验收。现有候选不匹配不能推出机器不存在有效密钥，也不能据此循环猜测。
- 源只处理目标公众号推送表并逐项核对永久链接的精确 `biz`，不读取普通私聊/群聊/联系人来补列表。加密快照不持久保留明文。
- 微信接收的推送可能漏掉未关注、未同步以及“发表未群发”的内容。搜狗普通 PC 低频核对只是补充，不是完整发表证明；正文必须独立通过精确身份验证。
- CAPTCHA、登录或共享访问限制停止受影响平台请求，不换身份、代理或入口绕行；单篇删除/付费保持具体缺口。
- `weekly-run` 默认绑定源或返回初始化提示，不自动转人工缓存。真实运行遵守持久化总暂停，发布代码不会解除它。

在这些前提都满足且用户授权真实运行后，流水线可读取推送、核对公开索引、低频抓正文、去重、按号 Word 和汇总。默认“已发现增量”仅推进独立已导出进度，不推进未知完整覆盖节点。`--require-complete` 要求真实独立全发表列表，当前没有已验收的这类适配器。

## 初始化不是普通更新动作

源码包含隔离的 biz-only 初始化开发模块，但不捆绑 helper、Frida 或密钥。必须读取实际安装的 setup Skill，由用户显式调用，预检精确目标并逐项确认。

开发初始化可能对临时应用副本作本地签名，并用 Frida 观察精确 salt 的派生；即使不改原版，也有重登、验证和安全退出风险。不要将其描述为普通重启或保证安全的一次性操作。当前交付不执行该流程、不安装依赖、不恢复后台。

## 兼容与验收

复用已有 helper 的只读快照/内存读取原语，固定版本和哈希变化会失败关闭。历史缓存路径和独立完整 Word 验证器仍保留；最新已验证缓存格式与使用方法见 [PASSIVE_CACHE_CAPTURE.md](PASSIVE_CACHE_CAPTURE.md)。离线合成测试、真实来源覆盖、文档验收、定时部署是不同验收层次。
